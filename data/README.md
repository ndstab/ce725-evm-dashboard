# Case study data

Generated by `generate_case_study.py`. Deterministic — rerunning it
reproduces these files exactly.

| File | Contents |
|---|---|
| `project.json` | Project constants: BAC, baseline length, data date, period labels |
| `wbs.csv` | Work breakdown structure and work package budgets |
| `baseline.csv` | Time-phased budget — planned value per package per period |
| `actuals.csv` | Cumulative percent complete and cost per period per package |

## These figures are assumed

A G+4 RCC academic block, BAC Rs 14.00 crore over 12 monthly periods, 19
work packages, data date at the end of Period 6.

Budgets are order-of-magnitude plausible for an institutional building of
this size built to CPWD DSR-style item rates. **They are not taken from
any tender, estimate or invoice, and no claim is made that they are
accurate unit rates.** The purpose of the data is to exercise the EVM
method, not to price a building.

The reasoning behind choosing synthetic over real project data is in
[`../docs/02-method-note.md`](../docs/02-method-note.md#22-why-synthetic-data).

## Note on units

`pct_complete_cum` is a **fraction** (0.45), not a percent (45). It is
also **cumulative**, while `ac_period_inr` is **per period**. That
asymmetry is deliberate: it is how each is naturally reported, a site
measuring total progress to date and accounts booking a month's cost.
